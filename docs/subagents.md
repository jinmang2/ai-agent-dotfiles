# 서브에이전트 — 직접 지정해서 쓰기

프레임워크가 "병렬로 해" 를 알아서 처리하게 두는 대신, 무엇을 몇 개 어떻게 띄울지
직접 쓰는 법.

## 정의

`~/.claude/agents/<이름>.md` — frontmatter + 시스템 프롬프트.

```markdown
---
name: inspector
description: 언제 이 에이전트를 쓰는지. 모델이 자동 선택할 때 이 문장을 본다.
tools: Read, Grep, Glob, Bash      # 생략하면 전부. 좁힐수록 안전하다
model: sonnet                       # 생략하면 상위 세션 모델을 물려받음
---

시스템 프롬프트. 역할·규칙·출력 형식을 여기에 쓴다.
```

저장소의 `claude/agents/inspector.md` 가 실물 예시다.

## 세 가지 호출 방식

| 방식 | 언제 |
|---|---|
| 이름을 지정 | "inspector 로 A, B, C 를 각각 봐줘" — 가장 통제된 방식 |
| 맡기기 | "이거 조사해줘" — 모델이 `description` 을 보고 고른다 |
| 프레임워크 | `/ultrawork` 류. 편하지만 무엇이 몇 개 떴는지 안 보인다 |

**직접 지정의 이점**: 몇 개가 뜨는지, 각자 뭘 받는지, 무엇을 돌려주는지가 보인다.
잘못 나오면 어느 에이전트의 프롬프트를 고칠지 알 수 있다.

## 병렬로 띄우기

한 번의 응답에서 여러 번 호출하면 동시에 돈다. 순차로 하려면 앞 결과를 기다렸다가
다음을 호출한다. 판단 기준은 하나다 — **서로의 결과가 필요한가.**

```
필요 없다  → 한꺼번에 띄운다 (파일 5개를 각각 조사)
필요하다   → 순차 (조사 결과를 보고 무엇을 고칠지 정한다)
```

프롬프트로 쓰면:

> `inspector` 로 `src/auth.ts` `src/db.ts` `src/api.ts` 를 **동시에** 조사해줘.
> 각각 따로 붙이고, 결과가 다 오면 공통 문제만 뽑아줘.

## 좋은 에이전트의 조건

- **범위가 하나다.** "조사한다" 는 좋고 "조사하고 고치고 테스트한다" 는 나쁘다.
  범위가 넓으면 병렬로 못 띄운다.
- **출력 형식이 정해져 있다.** 여러 개를 모아야 하므로 형식이 제각각이면 쓸모가 없다.
- **도구를 좁힌다.** 읽기만 하는 에이전트에 `Write` 를 주지 않는다.
- **결론을 내리지 않는다.** 판단은 결과를 다 본 호출자가 한다.

## 프레임워크를 걷어낼 때

`~/.claude/agents/` 와 `~/.claude/commands/` 가 프레임워크가 제공하던 것의 대체 자리다.
에이전트 카탈로그를 통째로 옮길 필요는 없다 — **실제로 호출하던 것만** 옮긴다.
무엇을 실제로 썼는지는 `~/.claude/history.jsonl` 에서 슬래시 명령을 세면 나온다.
